# このリポジトリについて

このリポジトリには3つの独立したプロジェクトが同居しています。

1. **感謝の一文字 — 結婚式Web演出**(`index.html`, `config.js`, `data/` ほか)
2. **人事研究 自動収集システム**(`config/sources.yml`, `scripts/collect_hr_research.py`, `reports/` ほか)

# 感謝の一文字 — 結婚式Web演出（17卓対応）

2026年8月1日・マリゾン福岡。ゲスト91名・17卓（A〜Q）それぞれに向けた
「感謝の一文字」漢字メッセージのWeb演出です。

卓ごとのQRコードを読み取ると `https://<ドメイン>/?t=A` のように
**同一ページ・パラメータ違い**のURLが開き、その卓のゲスト一覧が表示されます。
公開前は待機画面、公開後は名前カード（タップで漢字アニメーション）が出ます。

## ファイル構成

| ファイル | 役割 | 編集する？ |
|---|---|---|
| `index.html` | 全卓共通のテンプレート（デザイン本体） | 基本しない |
| `admin.html` | **当日の「公開する」ボタン**（管理ページ） | しない |
| `status.json` | 公開フラグ（管理ページが書き換える） | しない |
| `config.js` | **解禁方法**・署名・会場写真などの設定 | ✏️ する |
| `data/guests.csv` | **91名分のデータ入力用CSV** | ✏️ する |
| `data.js` | CSVから自動生成されるデータ（直接編集しない） | しない |
| `scripts/build_data.py` | CSV → data.js 変換スクリプト | しない |
| `scripts/make_qr.py` | QRコード17枚の一括生成 | しない |

## 解禁のしかた（2方式）

`config.js` の `unlockMode` で切り替えます。

- **`'button'`（デフォルト・推奨）** … 管理ページ `admin.html` の「公開する」ボタンで
  全17卓を一斉解禁。解禁前はカウントダウンなしの待機画面
  （「感謝」の落款がやわらかく呼吸するデザイン）が表示されます。
  ゲスト画面は5秒ごとに公開フラグ（`status.json`）を確認し、
  ボタンから最大30秒ほどで自動的に切り替わります（再読み込み不要）。
- **`'time'`** … 指定時刻になったら自動解禁。解禁前はカウントダウン表示。
  時刻は `unlockTime` / `unlockLabel` で設定、卓ごとの上書きは `tableOverrides`。

`failsafeTime` に時刻を入れておくと、**ボタン方式でもその時刻を過ぎたら自動で解禁**されます
（当日ネットワークやGitHubに万一問題があったときの保険。空なら無効）。

## 当日の公開ボタン運用（button方式）

### 事前準備（式の前日までに一度だけ）

1. GitHubで Fine-grained personal access token を作成
   （GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token）
   - Repository access: **このリポジトリのみ**
   - Permissions: **Contents → Read and write** のみ
   - 有効期限: 式の翌日まで
2. スマホで `https://<ドメイン>/admin.html` を開き、トークンを貼り付けて「この端末に保存」
3. 「公開する」→ ゲスト画面が切り替わるのを確認 → 「公開を取り消す」で待機画面に戻す
   （このリハーサルを必ず一度やっておく）

### 当日

1. 演出のタイミングで `admin.html` の「公開する」を押す
2. 30秒前後で「公開されました。ゲスト画面に反映されています。」と表示されたら完了
3. 反映確認が出てから司会にアナウンスしてもらうと確実です

※ `admin.html` のURLはゲストに配らないでください（トークンがなければ操作はできませんが、念のため）。

## ゲストデータの入れ方

1. `data/guests.csv` を編集する（Excel / Googleスプレッドシートで開いてCSV保存でOK。1行=1名）

   ```csv
   table_id,guest_name,kanji,yomi,message
   A,山田 太郎,山,やま,どっしりと構えて、いつも私たちを見守ってくれる...
   ```

   - `table_id` は A〜Q
   - メッセージ内で改行したい場合はセルを `"..."` で囲んで改行を入れる

2. 変換スクリプトを実行する

   ```bash
   python3 scripts/build_data.py
   ```

   空欄や不正な卓IDがあるとエラーで教えてくれます。成功すると卓ごとの人数が表示されるので、
   合計91名になっているか確認してください。

3. 生成された `data.js` ごとコミット＆プッシュ

## 動作確認（公開前でも中身を見る）

URLに `&preview` を付けると、公開前でもカード一覧を確認できます。

```
https://<ドメイン>/?t=A&preview
```

ローカルで確認する場合はリポジトリ直下で:

```bash
python3 -m http.server 8000
# → http://localhost:8000/?t=A&preview
```

## 公開（GitHub Pages）

1. このリポジトリをGitHubにプッシュ
2. リポジトリの **Settings → Pages → Branch: main（root）** を選んで保存
3. 数分後 `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます
4. データ更新時は「CSV編集 → `build_data.py` 実行 → コミット＆プッシュ」だけで反映

`config.js` の `statusUrl` はこのリポジトリの `main` ブランチを指しています。
リポジトリ名やブランチ名を変えた場合はそこも合わせて変更してください。

Netlifyの場合はリポジトリを連携（ビルドコマンドなし・公開ディレクトリ `/`）するだけです。
※ button方式の公開フラグはGitHub（raw URL）を参照するため、Netlifyでもそのまま動きます。

## QRコードの生成

公開URLが確定したら:

```bash
pip install qrcode pillow
python3 scripts/make_qr.py https://<ユーザー名>.github.io/<リポジトリ名>/
```

`qr/QR_A.png` 〜 `qr/QR_Q.png`（約1200px・誤り訂正レベルQ・
テーマカラーの藍色）が生成されます。4cm角印刷で約750dpi相当なので
印刷品質は十分です。生成後、必ず1枚スマホで読み取りテストをしてください。

## 知っておくと安心な制約

- GitHub Pages（無料）はリポジトリが公開になるため、技術に詳しい人が
  リポジトリを直接のぞけばメッセージ自体は事前に読めます（従来のtime方式と同じ制約です）。
  通常のゲスト操作では公開ボタンを押すまで見えません。
- `&preview` 付きURLは公開前でも中身が見えるので、ゲストには配らないでください。

# 人事研究 自動収集システム

**平日 7:00(日本時間)** に、人事(HR)に関するトレンドと最新研究を国内外から自動収集し、Markdownレポートを生成する仕組みです。GitHub Actions 上で完結するため、サーバーの用意や費用は不要です。

## レポートの構成

1. **🔥 本日のトレンド** — 直近の新聞・業界誌記事のタイトル・本文から
   人事関連キーワードの出現記事数を集計し、上位5つを表示
2. **📄 注目論文(3件)** — 収集した国内外の論文をトレンドとの関連度で
   スコアリングし、上位3件だけを厳選して掲載(関連トレンドを明記)
3. **📰 新聞 / 📚 業界誌 / 🏛 公的機関** — 各ソースの新着一覧

## 収集元(信頼できるソースに限定)

正確性を担保するため、収集元を **査読論文データベース・業界誌・新聞・公的機関** に限定しています。個人ブログ等の根拠が曖昧なコラムは含まれません。

| 区分 | ソース | 内容 |
|---|---|---|
| 海外論文 | [OpenAlex](https://openalex.org) | 世界最大級のオープン学術DB。査読付き論文のみ |
| 国内論文 | [J-STAGE](https://www.jstage.jst.go.jp) | JST運営の国内学術論文プラットフォーム |
| 新聞 | Google News検索(全国紙・通信社等を横断) | 人事・雇用・賃金関連の記事 |
| 新聞 | NHKニュース(経済) | 雇用・労働関連の報道 |
| 業界誌 | HR NOTE / HRzine | 人事・HR領域の専門メディア |
| 公的調査 | 厚生労働省 | 雇用・賃金・労働関連の統計/調査の新着 |
| 公的調査 | RIETI(経済産業研究所) | 雇用・人材関連のディスカッションペーパー等 |
| 海外研究 | NBER(全米経済研究所) | 労働経済学のワーキングペーパー |

## 動作の流れ

1. 平日 7:00 JST に GitHub Actions が起動(手動実行も可能)
2. 各ソースから直近数日の新着を取得し、キーワードでフィルタ
3. 過去に収集済みのものは `data/seen.json` で自動的に重複排除
4. 新聞・業界誌記事からトレンドキーワードを集計し、論文を関連度順に3件選定
   (選ばれなかった論文は、後日トレンドが変われば選ばれることがあります)
5. 論文の抄録・記事の本文抜粋から **日本語1〜2文の要約を自動生成**
   (GitHub Actions内蔵の GitHub Models を利用。無料・追加設定不要。
   失敗時は原文の抜粋を表示)
6. `reports/YYYY-MM-DD.md` にレポートをコミット
7. 同じ内容を **Issue として投稿** → GitHubの通知(メール)で受け取れる

## レポートの見方

- **Issues タブ**: 毎朝「📊 人事研究デイリーレポート」というIssueが作成されます。
  リポジトリを Watch(All Activity)しておけばメールでも届きます。
- **reports/ フォルダ**: 過去のレポートがすべて日付ごとに保存されています。

> 📧 メールで受け取りたい場合は、このリポジトリを Watch(All Activity)に設定してください。Issueが作成されるたびに通知が届きます。

## 手動で試す

GitHub の **Actions タブ → 「平日 人事研究レポート」→ Run workflow** で今すぐ実行できます。

ローカルで動かす場合:

```bash
pip install -r requirements.txt
python scripts/collect_hr_research.py
```

## カスタマイズ

検索キーワードや収集元はすべて [`config/sources.yml`](config/sources.yml) で管理しています。

- **トレンド判定キーワードの追加・変更**: `trends.keywords` を編集(表示ラベルと表記ゆれのリスト)
- **注目論文の件数変更**: `papers.limit` を編集(既定3件)
- **検索キーワードの変更**: `openalex.queries`(英語)/ `jstage.queries`(日本語)/ 新聞は `feeds:` の Google News `params.q` を編集
- **収集元の追加**: RSSフィードを `feeds:` に追記(`category` に `news`/`industry`/`public` を指定。`keywords` を指定するとタイトルで絞り込み)
- **収集期間の変更**: `window_days` を編集
- **実行タイミングの変更**: [`.github/workflows/daily-hr-research.yml`](.github/workflows/daily-hr-research.yml) の `cron` を編集(UTC表記。JSTから9時間引く)

## トラブルシューティング

- レポートに「⚠️ 取得に失敗しました」と出る場合、そのソースのRSS URLが変更された可能性があります。`config/sources.yml` のURLを最新のものに修正してください(各機関サイトの「RSS」ページで確認できます)。
- JILPT(労働政策研究・研修機構)は公式サイトにRSS配信がないため収集元に含まれていません。JILPTの新着はメールマガジンでの受け取りをおすすめします。
- スケジュール実行は、リポジトリに60日間活動がないとGitHubにより自動停止されます。Actionsタブから再有効化できます。
